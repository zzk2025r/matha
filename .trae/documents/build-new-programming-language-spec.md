# 计划：构建 Matha 编程语言的规格说明书

## Context（背景与动机）

用户希望从零构建一门**全新编程语言 Matha**。经过多轮澄清，确认其核心愿景与传统系统级语言（如 Rust/C）有本质不同，是一种独特的"**自然语言驱动 + 数学形式化 + 符号体系驱动 + 可读可验证**"的语言：

- **语言名称**：Matha
- **输入层**：以人类自然语言（中文 + 英文）为基础，用户用自然语言表达意图
- **核心层（"机械语言"）**：以**基础数学公式**构建代码，形式化基础为**集合论 + 类型论**，并拥有一套**自创符号体系**作为语法骨架，**标注**辅助明确目标、防止错乱
- **输出层**：生成可读的命令/代码，供人观看、理解与对比
- **并发模型**：CSP（goroutine + channel）
- **实现语言**：Python（编写编译器/解释器）
- **起步形态**：先完成**语言规格说明书**

由于"自然语言前端 + 集合论/类型论核心 + 自创符号体系 + CSP + Python 实现"这一组合极为特殊，市面上没有现成范本可直接套用，必须先撰写一份结构完整、定义清晰的规格说明书，作为后续编译器实现的契约。

本计划的目标是：**先产出规格说明书的完整结构与分章撰写方案**，并在用户确认后逐章落地。

---

## 语言设计愿景（规格说明书需贯穿的核心思想）

1. **自然语言亲和**：用户可用中英文自然语言描述意图，编译器解析为形式化核心
2. **数学严谨**：以集合论（集合、关系、映射、笛卡尔积）与类型论（类型、项、判断）为语义基础
3. **符号体系驱动**：Matha 拥有一套自创的核心符号体系，是语言的语法骨架（详见下节）
4. **标注明确**：通过 `*/文字/*` 标注明确目标、消解歧义、防止错乱
5. **可读可验证**：生成的"机械语言"命令本身可被人阅读、理解与对比
6. **CSP 并发**：轻量协程 + channel 通信

## Matha 核心符号体系（用户已设计，规格说明书需完整定义）

用户已为 Matha 设计了一套自创符号体系，作为语言的语法基础。规格说明书必须完整收录并精确定义每个符号的语义。

### 基础运算符号
| 符号 | 含义 |
|------|------|
| `+ - * /` | 算术运算（加 减 乘 除） |
| `=` | 等于 / 赋值 |
| `<` | 小于 |
| `>` | 大于 |
| `<<` | 角（角度 / 角标，语义待细化） |
| `>>` | 下一个（步进 / 迭代） |

### 变量与占位
| 符号 | 含义 |
|------|------|
| `？` | 变量占位符，可用任意字母替代 |

### 读取符号
| 符号 | 含义 |
|------|------|
| `【】` | 读取（方头括号） |
| `〔〕` | 读取（六角括号，与 `【】` 的语义层次差异待细化） |
| `【*/文字/*】` | 读取自然语言 |
| `【《文字》】` | 读取命令 |

### 输出符号
| 符号 | 含义 |
|------|------|
| `[]` | 输出 / 输出结果 |

### 标注符号
| 符号 | 含义 |
|------|------|
| `*/文字/*` | 标注字母（为字母 / 表达式附加语义标注） |

### 命令符号
| 符号 | 含义 |
|------|------|
| `《文字》` | 代表一个命令 |
| `#：` | 生成 / 运行 |
| `#：《文字》` | 生成命令 |

### 分隔符号
| 符号 | 含义 |
|------|------|
| `|` | 分格（分隔单元 / 分隔符） |

> **待细化**：`<<`（角）、`〔〕` 与 `【】` 的语义层次差异、`#：` 与 `#：《文字》` 的区别、`？` 与字母的替代规则等，需在对应章节中精确定义。这套符号体系是 Matha 区别于其他语言的核心特征。

## 规格说明书结构（共 20 章）

按用户"代码文件超 1000 行需拆分"的偏好，规格说明书拆分为多个 Markdown 文件，每章独立成文。

### 第一部分：总览

- **01-设计原则.md** — 六大原则（自然语言亲和、数学严谨、符号体系驱动、标注明确、可读可验证、CSP 并发）的展开与权衡

### 第二部分：词法与语法
- **02-词法结构.md** — 字符集（中英文）、Matha 核心符号体系（`？+-*/=<> << >> 【】〔〕 [] */文字/* 《》 #： |`）的词法定义、标识符、字面量、注释
- **03-自然语言前端.md** — 自然语言输入格式、中英文解析规则、`【*/文字/*】`读取自然语言、意图提取、自然语言→数学核心的映射、歧义消解（`*/文字/*`标注的作用）

## 验证方法

规格说明书的"验证"以**自洽性与可读性**为标准：

1. **符号体系完整性**：用户设计的全部符号在 `02 词法结构` 定义、在 `04 数学核心`/`06 表达式`/`13 可读输出层` 中有明确语义，`19 附录`有速查表，无遗漏
2. **横向一致性**：各章引用的符号、关键字、类型在 `02 词法结构` 与 `05 类型系统` 中均有定义，无悬空引用
3. **纵向可追溯**：`18 示例程序集` 中每个示例，能从 `00 概述` 的三段式（自然语言→数学核心→可读输出）走通，所用符号均在 `17 EBNF` 中有产生式
4. **EBNF 可解析**：`17 完整语法EBNF` 能被标准 EBNF 解析器（如 Python 的 `lark`/`pyparsing`）解析无语法错误
5. **Hello World 走查**：`00 概述` 中的 Hello World 示例（用 Matha 符号书写），能手动追查到每章定义，证明规格自洽
6. **术语对照**：`19 附录` 的中英术语表覆盖正文所有术语

完成 M1 后即可进行第一次走查；M4 完成后进行全量验证。
