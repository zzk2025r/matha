# 07 - 语句与控制流

> 本章定义 Matha 的语句结构、绑定与赋值、条件、循环（含 `>>` 步进）、模式匹配、块与 `|` 分格的用法。

---

## 1. 语句终止与块

### 1.1 语句终止
- 语句以**换行**终止（Python 风格）。
- 一条语句可跨行时，用 `|` 显式延续或保持在同一括号内。
- 在 `{ }` 代码块或 `@:a,b,c` 中，`，`（中文逗号）可并列多条语句/设定项。

### 1.2 块的两种形式

Matha 的块有**两种等价形式**，可混合使用（已确认：`{代码}` 代表「一串代码是整体」）：

#### 块形式一：缩进块（默认）
- 块用**缩进**表示（建议 3 空格）。

```
？x >> S
   sum = sum + x        (* 缩进体属于循环 *)
[] sum                     (* 循环外 *)
```

#### 块形式二：{ } 代码块 / 整体串（推荐在机械单元顶层使用）
- 用大括号 `{ ... }` 把一串语句括起来，**明确表示是一个整体/一串代码**。
- 与集合构造的歧义消解：`{` 后紧跟 `变量 |` 或 `值, 值, 值` 为集合；其余语境下外层的 `{ ... }` 为代码块。

```
#：{
   【*/自然语言与叙述/*】
   #：《小米在 c>>d 段 1/4 下车，求小米到 a 点距离》
   @:a>>b=100米，b>>c=50米，c>>d=(a>>c)*3，a*/酒店/*
   #：100+50=150，150+150*3/4=262.5
   #：[262.5米]
}
```

> 推荐：**最外层机械单元用 `{ }` 明确边界**；内层控制流（循环、条件）用缩进块。两者语义等价——**{ } 块 = 一串语句的整体** = 按缩进形成的语句序列。

## 2. 声明与绑定 + @ 设定语句

### 2.1 绑定语句

```
<variable> = <expr>
```

将表达式的值绑定到变量。变量可带标注（[05 §7](05-类型系统.md)），`>>` 出现在被赋值者位置时表示路径/距离（[04 §5.3](04-数学核心（机械语言）.md)）：

```
？sum */Int/* = 0
S */Set[Int]/* = { x | 1 <= x <= 10 }
a>>b = 100米              (* 路径绑定：a 到 b 的距离 = 100 米 *)
```

### 2.2 `=` 的赋值 vs 相等

- **赋值**：`=` 出现在语句首位、左侧为变量（或路径 `a>>b`）时（`x = 5`、`a>>b=100米`）。
- **相等判断**：`=` 出现在表达式位置（集合条件、三元条件等）。
- 消解由语法位置决定（见 [06 §3](06-表达式与运算符.md)）。

### 2.3 @ 设定语句（双形式 + 段编号形式）

`@` 设定语句可出现在顶层或机械单元内，用于批量声明/条件设定。两种等价形式（无段号）外，**另有带段号形式 `@N(...)` / `@N:xxx`**（M3 已确认，与 `#N：` 段号配对）：

```
@(a1 | d | c6)                     (* 无段号：形式一：括号 + | 分格 *)
@:a>>b=100米，b>>c=50米            (* 无段号：形式二：@: 前缀 + 中文逗号分格，适合手写 *)
@1(a | b | c)                      (* 带段号 N=1：括号分格 *)
@2：变量                           (* 带段号 N=2：@: 前缀，全角冒号也合法（M3 已确认） *)
@3:a>>b=100米，c>>d=50米           (* 带段号 N=3：前缀分格 *)
```

- 每一项可以是：变量名、变量 + 标注、或完整绑定（含路径绑定）。
- 在 `{ }` 块内的 `@:` / `@N:` 形式可与其他语句同列，也可独占一行。
- 详细语法见 [02 §2.8](02-词法结构.md) 与 [04 §5.10](04-数学核心（机械语言）.md)。

### 2.4 段语句：可编辑代码的 5 步结构（段 N）

机械单元内使用 `#N：命令/公式/计算/输出` 与 `@N：变量` 构成一段完整的分步语句。段号从 1 起排列（M3 已确认）。

#### 2.4.1 段内 5 步固定顺序（不可调换）

每段 N 按以下顺序排列语句（与 [04 §5.12](04-数学核心（机械语言）.md) 对齐）：

| 顺序 | 语句形式 | 说明 | 多句分隔 | 可否省略 |
|---|---|---|---|---|
| ① | `#N：【命令】` 或 `#N：《命令》` | 段 N 的命令/目标（命令两种写法等价） | **换行**：每条命令独立一行 | 可省略（若本段无命令目标） |
| ② | `@N：变量` / `@N(a,b,c)` | 段 N 的变量/设定（双形式均可） | `@N:` 用**逗号**分隔；`@N(...)` 用 `\|` 分隔 | 可省略（若本段不需变量） |
| ③ | `#N：？公式` | 段 N 的公式模板（`？` 占位 / `？+？=？` 通用公式）——**把数学公式简化/抽象化** | **逗号**分隔多条：`？+？=？，？*？/?=？` | 可省略（若本段无需通用公式） |
| ④ | `#N：字母公式/直接计算` | 段 N 的计算过程（字母代入精确化 / 直接写算式）——**把 `？` 公式精确化到具体字母/数值** | **逗号**分隔多条 | 可省略（若本段不需计算步骤） |
| ⑤ | `#N：[输出/结果]`（主输出行）<br>`#N：…N（x/y）[全局编号][……（g_x/g_y）][【路径】]`（循环+路径独立一行） | 段 N 的主输出 + 双重循环 + 可选路径引用（M3.2 推荐分行书写；同行写法仍允许作简写） | 主输出行固定一行；循环+路径独立一行（可同行作简写） | 通常不可省略（段的核心目标） |

> **设计说明（M3.1 新增 + M3.2 细化）：**
> - 「命令 → 变量 → `？`公式 → 字母公式 → 输出」的顺序是**固定的**，不可调换；但每步可按需省略。
> - `？公式` = **简化/抽象化**数学公式（用占位符 `？` 表达通用结构）。
> - `字母公式` = **精确化** `？` 公式（把 `？` 替换为具体字母变量或直接数值运算）。
> - 命令用**换行**分格（每条命令一行）；公式/变量用**逗号**分格。
> - **命令与输出独立拥有读取能力**（M3.2 强调）：无需 `>>` 链式即可单独读取 URL / 文件 / 文件夹 / 端口。
> - **段内允许多条命令/变量/公式并存**（M3.2 强调）：当另一段的命令或输出匹配该段某条变量/公式的需求时，可直接**选用/调用**。

#### 2.4.2 多命令链式执行（`>>` 链式）

**触发条件（M3.2 强调）：当单条命令或单条输出不足以完成任务时**，才启用 `>>` 链式；否则优先使用单条命令/输出的独立读取能力。

使用 `>>` 链式连接多条命令、输出或通用语句：

```
#：【启动服务】>>【读取配置】>>【执行计算】    (* 多命令链式：逐条执行 *)
#：[结果1]>>[结果2]>>[结果3]                (* 多输出链式 *)
#：【命令】>>@:变量>>#：公式                (* 通用语句链式 *)
```

**`>>` 链式规则（M3.1 已确认）：**
- `>>` 链式为**通用链式**，可连接任意语句类型（命令、输出、设定、公式、变量等）。
- `>>` 的链式语义与原有的「步进/属于/路径」三语义通过**位置上下文**消解：
  - 链式语境：`>>` 两侧均为同类语句（`【】>>【】`、`[]>>[]`、`@:>>@:` 等）且不在循环头/绑定左侧 → 链式
  - 循环语境：`？x >> S` 后跟缩进块 → 步进迭代
  - 表达式语境：`x >> S` 在表达式内部 → 属于判断
  - 绑定语境：`a>>b=...` 在赋值左侧 → 路径/距离

#### 2.4.3 段级输出允许的五种变体

1. 仅段级循环：`#1：[输出]…1（0/1）`
2. 段级 + 全局编号：`#2：[输出]…2（0/4）00001`
3. 段级 + 全局编号 + 全局循环：`#2：[输出]…2（0/4）00001……（0/1）`
4. 全局循环 + 路径引用（同行）：`#2：[输出]…2（0/4）01……（0/2）【路径】`
5. 全局循环 + 路径引用（分行）：
   ```
   #2：[输出]…2（0/4）01……（0/2）
   #：【路径】
   ```

#### 2.4.4 公式共享与调用

多段代码中的变量、`？`公式、字母公式可**跨段共享**：当某段的命令与输出匹配另一段的需求时，可直接引用前一段已定义的变量/公式/计算结果。

```
#1：【计算面积】          (* 命令 1 *)
@1:长=5米，宽=3米         (* 变量 *)
#1：？*？=？              (* ？公式：抽象化 *)
#1：长*宽=15             (* 字母公式：精确化 *)
#1：[15平方米]…1（0/1）  (* 输出 *)

#2：【计算总价】          (* 命令 2：与 #1 共享变量/公式 *)
@2:单价=10元/平方米
#2：？*？=？              (* 复用 ？公式 *)
#2：面积*单价=150         (* 引用 #1 结果，精确化 *)
#2：[150元]…2（0/4）01……（0/2）  (* 输出 + 全局编号 + 全局循环 *)
```

省略号**硬性区分**（M3 已确认）：
- 段级循环：单 `…`
- 全局循环：双 `……`

括号半/全角均合法（M3 已确认）：`(0/1)` 与 `（0/1）` 等价。

#### 2.4.5 命令/输出的通用读取能力（M3.1 新增 + M3.2 升格为独立一等能力）

**核心语义（M3.2 强调）：命令与输出结果各自独立拥有读取能力——无需 `>>` 链式即可直接读取 URL / 网站 / 本地文件 / 文件夹 / 端口等资源。**

支持的资源类型（命令、输出**各自独立**支持所有类型）：
- 网址 / 网站（URL）
- 本地文件 / 文件路径
- 文件夹 / 目录路径
- 端口 / 网络接口

```
#：【http://example.com/api】   (* 命令：直接读取网址 *)
#：【/data/config.yaml】       (* 命令：直接读取本地文件 *)
#：【d:\trae\docs\】           (* 命令：直接读取文件夹 *)
#：【localhost:8080】          (* 命令：直接读取端口 *)
#：[http://example.com/api]    (* 输出：直接从网址读取并产出结果 *)
#：[/data/config.yaml]         (* 输出：直接读取文件并输出 *)
```

**只有在单条命令/单条输出无法满足需求时**，才升级为 `>>` 链式：
```
#：[读取结果]>>[解析结果]>>[入库结果]   (* 多输出链式 *)
#：【读取文件】>>【解析 JSON】>>【写回 DB】  (* 多命令链式 *)
```

### 2.5 文件拆分语句：跨文件串联

`{ }` 代码块的尾行可写文件拆分语句，把完整代码分散在多个文件中（M3 已确认）。**路径引用 `【路径】` 既可与输出追踪写在同一行（M3.1 已确认），也可独立成行**：

| 语句 | 语义 |
|---|---|
| `#：【文件】` | 当前文件中的这部分代码到此结束（文件尾标记） |
| `#：【路径】` 或 `#：【文件名】` 或 `#：【文件夹路径】` | **用于输入文件名称/文件夹（路径）**（M3 已确认）；即按路径查找、关联其他文件。绝对路径（如 `d:\trae\...`）与相对路径（如 `../data/`）都合法 |
| `<输出追踪>【路径】` | **同行写法**：路径引用直接跟在输出追踪后面（M3.1 已确认） |
| 独立一行的 `<global_code_id>` | 跨文件绑定：下一个文件最开头单独写一行全局编号，把此文件与原编号的其他文件串联（如 `00001` 单独一行） |

读取符号两种形式均可：`【】` 或 `〔〕`（功能等价）。详细示例见 [04 §5.14](04-数学核心（机械语言）.md)。

## 3. 条件

### 3.1 三元表达式（符号式）

```
<cond> ? <then> : <else>
```

- 半角 `?` `:` 与全角占位 `？` 不冲突。
- 返回 `then` 或 `else` 的值。

```
max = a > b ? a : b
```

### 3.2 块式条件（草案）

```
<cond>
   <then 块>
否则
   <else 块>
```

- `否则`（或 `else`）为关键字草案。
- 多分支：`否则 <cond2>` 链式。

```
x > 0
   [] "正"
否则 x < 0
   [] "负"
否则
   [] "零"
```

> **待确认**：块式条件是否引入 `否则`/`else` 关键字，或纯用 `? :` 与自然语言前端 `【*/如果/*】` 表达。

## 4. 循环

### 4.1 步进循环（`>>`）

```
<variable> >> <set_expr>
   <循环体>
```

`x` 依次取集合中的每个元素，执行循环体：

```
？x >> S
   sum = sum + x
```

### 4.2 条件循环（草案）

```
<cond> ?
   <循环体>
```

当 `cond` 为真时重复执行（`while` 语义）。需与三元表达式消歧——当 `?` 后跟缩进块而非 `: else` 时为循环。

> **待确认**：条件循环语法。候选：`cond ? { body }`（块）、`while cond`（关键字）、或仅保留 `>>` 步进而无显式 while（用递归替代）。

### 4.3 提前退出（草案）

- `<<break`：跳出循环（`<<` 此处复用为控制标记，待确认）。
- `<<next`：跳到下一次迭代。

> **待确认**：`<<` 在控制流中的复用是否与"角度运算"冲突。倾向另立符号。

## 5. 模式匹配（草案）

```
match <expr>
   | <模式1> -> <结果1>
   | <模式2> -> <结果2>
   | _ -> <默认>
```

`|` 分格各分支，`->` 分隔模式与结果。模式可为字面量、变量、`>>` 属于判断：

```
match n
   | 0 -> "零"
   | n >> S -> "在集合中"
   | _ -> "其他"
```

> **待确认**：是否引入 `match` 关键字，或用纯符号 `| 模式 -> 结果`。详见 [09-用户自定义类型](09-用户自定义类型.md)。

---

## 6. `|` 分格的用法汇总

| 语境 | 用法 | 示例 |
|------|------|------|
| 集合构造 | 分隔变量与条件、并列条件 | `{ x \| 1 <= x <= 10 }`、`{ (x,y) \| x >> A \| y >> B }` |
| 序列 | 分隔并列表达式 | `a \| b \| c` |
| 模式匹配 | 分隔分支 | `\| 模式 -> 结果` |
| 行延续 | 显式延续语句 | `长表达式 \| 继续` |

## 8. EBNF 摘要

```ebnf
<mech_stmt>  = <binding> | <if_stmt> | <loop_stmt> | <match_stmt> | <output> | <output_trail>
             | <set_up> | <set_up_seg> | <gen_stmt> | <gen_stmt_seg> | <file_marker> | <global_id_stmt>
             | <chain_stmt> | <expr> ;
<binding>    = ( <variable> | <path_expr> ) , [ <annotation> ] , "=" , <expr> ;
<path_expr>  = <variable> , ">>" , <variable> ;

(* 无段号 / 带段号（#N：）—— 通用生成语句 *)
<gen_stmt>      = <generate> , ( <command_literal> | <chained_command> | <expr> | <output_trail> ) ;
<gen_stmt_seg>  = "#" , <seg_id> , ( ":" | "：" ) , ( <command_literal> | <chained_command> | <expr> | <output_trail> ) ;

(* 命令字面量：《文字》 与 【文字】 两种写法共存（M3.1 已确认） *)
<command_literal> = <cn_command_literal> | <bracket_command_literal> ;
<cn_command_literal> = "《" , <command_text> , "》" ;
<bracket_command_literal> = "【" , <command_text> , "】" ;
<command_text> = <identifier> | <natural_lang_fragment> ;

(* 命令链式：>> 连接多条命令（通用链式，M3.1 已确认） *)
<chained_command> = <command_literal> , { ">>" , ( <command_literal> | <output_trail> | <set_up> | <gen_stmt> | <gen_stmt_seg> ) } ;

<seg_id>        = <digit_1_9> , { <digit> } ;                  (* 段号从 1 起，任意位整数 *)
<digit_1_9>     = "1" | "2" | "3" | "4" | "5" | "6" | "7" | "8" | "9" ;

(* 设定：双形式 + 段编号形式 *)
<set_up>         = <set_up_paren> | <set_up_prefix> ;
<set_up_seg>     = <set_up_seg_paren> | <set_up_seg_prefix> ;
<set_up_paren>   = "@" , "(" , <set_up_item> , { "|" , <set_up_item> } , ")" ;
<set_up_prefix>  = "@" , ( ":" | "：" ) , <set_up_item> , { ( "，" | "," ) , <set_up_item> } ;
<set_up_seg_paren>  = "@" , <seg_id> , "(" , <set_up_item> , { "|" , <set_up_item> } , ")" ;
<set_up_seg_prefix> = "@" , <seg_id> , ( ":" | "：" ) , <set_up_item> , { ( "，" | "," ) , <set_up_item> } ;
<set_up_item>    = ( <variable> | <path_expr> ) , [ <annotation> ] , [ "=" , <expr> ] ;

(* 输出 + 段循环 + 子文件 + 全局编号 + 全局循环 + 文件路径（M3.3：按位置区分子文件/文件） *)
<output_trail>       = <output>
                     , [ <seg_loop_suffix>
                       , [ <subfile_ref> ]                        (* 段循环后：子文件，| 分隔多个 *)
                       , [ <global_code_id> ]
                       , [ <global_loop_suffix> , [ <file_ref> ] ]   (* 全局循环后：文件路径 *)
                       ] ;
<subfile_ref>        = ( "【" | "〔" ) , <path_content> , { "|" , <path_content> } , ( "】" | "〕" ) ;
<file_ref>           = ( "【" | "〔" ) , <path_content> , ( "】" | "〕" ) ;
<seg_loop_suffix>    = "…" , [ <seg_id> ] , <loop_fraction> ;
<global_loop_suffix> = "……" , <loop_fraction> ;
<loop_fraction>      = ( "(" | "（" ) , <digit_seq> , "/" , <digit_seq> , ( ")" | "）" ) ;  (* 半/全角括号等价 *)
<digit_seq>          = <digit> , { <digit> } ;
<global_code_id>     = <digit_seq> ;                                       (* 任意位，不固定 *)

(* >> 通用链式：可连接任意语句类型（M3.1 已确认） *)
<chain_stmt>         = <mech_stmt> , { ">>" , <mech_stmt> } ;

(* 文件拆分 *)
<file_marker>    = <generate> , ( "【" | "〔" ) , <path_content> , ( "】" | "〕" ) ;
<path_content>   = "文件" | <identifier> | <path_literal> ;
<global_id_stmt> = <global_code_id> ;                                       (* 跨文件单独一行全局编号 *)

<if_expr>    = <expr> , "?" , <expr> , ":" , <expr> ;
<loop_step>  = ( <placeholder> , <variable> | <variable> ) , ">>" , <expr> , <block> ;
<match_stmt> = "match" , <expr> , { "|" , <pattern> , "->" , <expr> } ;
<block>      = <indent_block> | <code_block> ;
<indent_block> = <newline> , <indent> , { <mech_stmt> } ;
<code_block>   = "{" , <newline> , { <mech_stmt> , <newline> } , "}" ;
```
