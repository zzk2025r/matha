# 15 - 编译执行模型

> 本章定义 Matha 的编译与执行模型：从自然语言源文本到执行结果的完整流程、Python 实现的编译器架构、目标平台与 FFI。

---

## 1. 编译流程总览

Matha 程序从源文本到结果，经过六个阶段（见 [00 §6](00-前言与概述.md)）：

```
① 词法分析        源文本 → Token 流（识别 Matha 符号体系）
② 分层解析        Token → 分层 AST（自然语言意图块 + 机械语言单元）
③ 意图提取与映射   自然语言意图 → 数学核心构造（mech_body）
④ 类型检查        标注约束验证（*/文字/*）
⑤ 命令生成        #：触发，生成《文字》命令与 [] 输出
⑥ 执行 / 输出      Python 运行时执行，或可读输出层展示
```

---

## 2. 各阶段说明

### 2.1 词法分析

- 输入：UTF-8 源文本。
- 输出：Token 流（见 [02 §8](02-词法结构.md)）。
- 关键：**最长匹配**处理 `<<`、`>>`、`<=`、`>=`、`#：`、`*/.../*` 等多字符符号。
- Unicode 符号（`？【】〔〕《》`）按字面 Token 识别。

### 2.2 分层解析

- 自然语言意图块（`【*/文字/*】`）与机械语言单元（`#：`）分别解析。
- 输出：分层 AST，保留自然语言原文与机械语言结构。

### 2.3 意图提取与映射

- 自然语言前端（[03](03-自然语言前端.md)）将意图块映射为 mech_body。
- 默认规则解析；可选 NLP/AI 辅助（待确认）。
- 映射失败报错，提示用机械语言显式书写。

### 2.4 类型检查

- 基于 `*/文字/*` 标注与环境进行双向类型检查（[05](05-类型系统.md)）。
- 错误以可读输出层格式报告（[13 §6](13-可读输出层.md)）。

### 2.5 命令生成

- `#：` 触发执行；`#：《命令》` 生成命令对象。
- `[]` 标记输出点。

### 2.6 执行 / 输出

- **执行模式**：Python 运行时求值 AST。
- **对比模式**：`--compare` 输出三段对照（[13 §5](13-可读输出层.md)）。

## 3. Python 实现架构

编译器用 Python 实现，模块化：

```
matha/
├── lexer.py           # 词法分析（符号体系识别）
├── parser.py          # 分层解析 → AST
├── nl_frontend.py     # 自然语言前端（意图模板匹配）
├── type_checker.py    # 类型检查（标注验证）
├── codegen.py         # 命令生成
├── runtime.py         # 执行运行时
├── output.py          # 可读输出层
└── main.py            # 编译器入口（CLI）
```

### 3.1 关键依赖（草案）

| 组件 | 候选 Python 库 |
|------|---------------|
| 词法/解析 | `lark` 或 `pyparsing`（EBNF 驱动） |
| 中文分词 | `jieba`（自然语言前端） |
| NLP/AI（可选） | `transformers` / `spacy`（待确认） |
| 并发运行时 | `asyncio`（协程映射） |

### 3.2 AST 设计

- 分层 AST：`NLBlock`（自然语言意图）、`MechUnit`（机械单元）、`Command`（命令）。
- 类型标注作为 AST 节点属性，供类型检查器遍历。

## 4. 运行时

### 4.1 执行策略

- **解释执行**：直接遍历 AST 求值（原型阶段）。
- **后续优化**：编译到字节码 + VM，或转译到 C/LLVM（待确认，见 [00](00-前言与概述.md) 待决策项）。

### 4.2 并发运行时

- Matha 协程映射到 Python `asyncio` 协程。
- channel 用 `asyncio.Queue` 实现。
- 阻塞 IO 操作映射到 `asyncio` 异步原语。

### 4.3 内存

- 依赖运行时 GC（Python GC），不提供手动内存管理——这与"形式化高级语言"定位一致（见 §6）。
- 语言语义层不暴露指针/内存布局；远期若需原生性能，通过转译后端处理，而非在语言层引入手动管理。

## 5. 目标平台与 FFI

### 5.1 目标平台

| 阶段 | 目标 |
|------|------|
| 原型 | Python 解释执行 |
| 中期 | 字节码 + 自定义 VM |
| 远期（可选） | 转译到 C / LLVM IR / WASM |

### 5.2 FFI（与 C 互操作，草案）

```

   printf : String -> Unit
   | sqrt_c : Float -> Float
}
```

## 6. 语言定位：形式化高级语言

Matha 的最终定位为**形式化高级语言**（已确认）。

虽然用户最初选择"系统级语言"目标，但实际设计走向"自然语言驱动 + 数学形式化 + 可读可验证"——三层显式架构、依赖 Python GC 而非手动内存管理、以集合论与类型论为语义基础。这些特征使 Matha 更接近**形式化高级语言**，而非传统系统级语言（C/Rust）。

**定位含义**：

| 维度 | 形式化高级语言定位下的选择 |
|------|--------------------------|
| 内存管理 | 依赖运行时 GC（Python GC），不提供手动管理 |
| 执行模型 | 解释执行 → 字节码 VM，远期可选转译到 C/LLVM/WASM |
| 抽象层次 | 以数学构造（集合/关系/映射/类型）为一等公民，而非指针/内存布局 |
| 核心价值 | 自然语言亲和、数学严谨、可读可验证，而非零成本抽象/裸金属控制 |
| 适用领域 | 形式化规格、集合/数据处理、并发系统、教学研究、自然语言驱动原型 |

> **与系统级语言的关系**：Matha 不追求替代 C/Rust 的系统级场景。远期若需原生性能，可通过"转译到 C/LLVM"作为可选后端（见 §5.1），但语言语义层不暴露手动内存管理。

## 7. CLI 接口（草案）

```
matha run <file>              # 运行
matha check <file>            # 仅类型检查
matha --compare <file>        # 三段对照输出
matha --emit ast <file>       # 输出 AST
```
