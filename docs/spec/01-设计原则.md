# 01 - 设计原则

> 本章展开 Matha 的六大设计原则，阐明每条原则的定义、动机、在语言中的体现，以及为之接受的权衡。这六大原则是后续所有章节的设计准则与裁决依据。

---

## 原则一：自然语言亲和（Natural Language Affinity）

### 定义
用户可以用中文与英文自然语言直接表达编程意图，编译器负责将意图提取、映射为形式化的数学核心代码。

### 动机
人脑的思考方式天然是自然语言的。强迫程序员在思考的第一步就切换到形式化语法，会损失意图表达的丰富性与直觉性。Matha 把自然语言作为**输入入口**，而非可选项。

### 体现
- `【*/标注/*】 ... 自然语言 ...` 语法显式标记一段自然语言意图（详见 [03-自然语言前端](03-自然语言前端.md)）。
- 自然语言段落通过 `*/标注/*` 与机械语言核心建立引用关联。
- 中英文均可作为意图表达语言。

### 权衡
- **代价**：自然语言有歧义，需要 `*/文字/*` 标注与规则约束来消解；解析复杂度上升。
- **边界**：Matha 不追求"任意自然语言都能解析"，而是支持**受约束的自然语言子集**，超出部分需用机械语言显式书写。

---

## 原则二：数学严谨（Mathematical Rigor）

### 定义
Matha 的核心层（机械语言）以**集合论**与**类型论**为形式化基础。所有程序构造都是数学构造：集合、关系、映射、类型、项、判断。

### 动机
数学是消除歧义的最可靠工具。把代码建立在集合论与类型论之上，使程序同时具备：
- **可执行性**（能被编译器运行）
- **可证明性**（能被形式化推理验证）

### 体现
- 集合构造：`S = { x | 条件 }`（详见 [04-数学核心](04-数学核心（机械语言）.md)）。
- 类型判断：每个项有类型，类型检查在编译期完成（详见 [05-类型系统](05-类型系统.md)）。
- 运算符语义对应数学定义（`+` 为加法、`<` 为序关系等）。

### 权衡
- **代价**：对非数学背景的用户有学习门槛。
- **当前取舍**：暂不引入依赖类型（Dependent Types），以简单类型 + 参数化类型 + `*/文字/*` 标注起步；依赖类型留待后续版本。

---

## 原则三：符号体系驱动（Symbol-System Driven）

### 定义
Matha 拥有一套**自创符号体系**，作为贯穿三层的统一语法骨架。每个符号有明确、唯一的语义。

### 动机
传统语言的关键字（`if`、`for`、`return`）受制于自然语言，跨语言不统一且语义冗长。Matha 用精炼的符号承载核心语义，使代码紧凑、跨语言中立，并让"符号即语义"成为可读性基础。

### 体现
完整符号表见 [00-前言与概述 §术语表](00-前言与概述.md) 与 [19-附录](19-附录.md)。核心符号分类：

| 类别 | 符号 |
|------|------|
| 运算 | `+ - * / = < > << >>` |
| 占位 | `？` |
| 读取 | `【】 〔〕` |
| 输出 | `[]` |
| 标注 | `*/文字/*` |
| 命令 | `《文字》 #：` |
| 分隔 | `|` |

### 权衡
- **代价**：自创符号体系对新手不直观，需要查阅符号表；部分符号（`<<`、`〔〕`）的语义需精化（见 M1 走查待确认项）。
- **收益**：一旦掌握，代码极为紧凑且语义无歧义。

---

## 原则四：标注明确（Annotation Clarity）

### 定义
通过 `*/文字/*` 标注为字母、表达式或意图明确目标、附加语义、消解歧义，**在错误发生之前防止错乱**。

### 动机
自然语言的歧义与类型的不确定性是程序错误的两大根源。标注提供一种**轻量、显式**的机制，让程序员在书写时即声明意图，编译器据此检查。

### 体现
- 意图标注：`【*/问候/*】` 标注一段自然语言意图的用途。
- 类型/约束标注：为变量与表达式附加约束（详见 [05-类型系统](05-类型系统.md)）。
- 防错：标注与实际构造不符时，编译器在编译期报错。

### 权衡
- **代价**：书写时需额外标注，略增篇幅。
- **边界**：标注应保持轻量，避免退化为冗长的声明式样板。

---

## 原则五：可读可验证（Readable & Verifiable）

### 定义
Matha 生成的机械命令本身必须可被人阅读、理解与对比。**若输出无法被人读懂，则无法被信任**。

### 动机
编译器是复杂的、可能出错的。如果生成的代码是黑箱，人无法检验其正确性。Matha 把"可读输出"作为一等公民，让人与机器能在同一套符号上对话。

### 体现
- `[]` 输出符号生成可读结果（详见 [13-可读输出层](13-可读输出层.md)）。
- `《文字》` 命令以可读形式展示。
- 三段式链路（自然语言 → 数学核心 → 可读输出）显式可见，便于逐层对比检验。

### 权衡
- **代价**：生成可读输出需要额外的格式化与展示工作。
- **收益**：提升可信度与可调试性，尤其适合形式化推理与教学场景。

---

## 原则六：CSP 并发（Communicating Sequential Processes）

### 定义
Matha 的并发模型基于 CSP：轻量协程（goroutine 风格）通过 channel 通信，**不通过共享内存**传递状态。

### 动机
共享内存 + 锁的并发模型易错、难推理。CSP 把并发单元隔离，通过显式的 channel 通信，使并发行为可组合、可推理，契合 Matha"可读可验证"的整体哲学。

### 体现
- 协程语法（详见 [11-并发模型](11-并发模型.md)）。
- channel 作为一等值，可传递、可类型化。
- `select` 等同步原语。

### 权衡
- **代价**：对习惯共享内存并发的用户有范式迁移成本。
- **边界**：底层运行时（Python 实现）仍需映射到 OS 线程或协程，性能与原生 CSP 实现可能有差异。

---

## 原则间的优先级与裁决

当原则发生冲突时，按以下优先级裁决：

```
数学严谨 > 标注明确 > 可读可验证 > 符号体系驱动 > 自然语言亲和 > CSP 并发
```

即：若某设计能提升自然语言亲和性但损害数学严谨性，则优先保证数学严谨。例外情况在各章中显式说明。

---

## 与现有语言的对照

| 原则 | Matha | 对照语言 |
|------|-------|---------|
| 自然语言亲和 | 三层显式，`【*/文字/*】` 读取 | 与 Wolfram 自然语言输入有相似意图，但 Matha 显式分层 |
| 数学严谨 | 集合论 + 类型论核心 | 类似 Lean/Coq 的形式化基础，但更轻量 |
| 符号体系 | 自创符号骨架 | 类似 APL 的符号驱动，但符号体系自洽且中英文友好 |
| 标注 | `*/文字/*` 统一标注 | 借鉴 Python 装饰器 / Rust attribute，但更轻量 |
| 可读输出 | `[]` 与 `《文字》` 一等输出 | 独有 |
| CSP 并发 | 协程 + channel | 同 Go |

Matha 的独特性在于：**把上述六者整合进一个显式三层架构**，而非单点突破。
