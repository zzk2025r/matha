# 00 - 前言与概述

> 本章是 Matha 语言规格说明书的开篇，定义语言的设计动机、愿景、哲学、适用领域，并通过三段式 Hello World 示例展示语言全貌。

---

## 1. 设计动机

### 1.1 现有语言的鸿沟

当今编程语言大致分为两极：

- **自然语言端**：人类用日常语言思考与沟通，但自然语言歧义丛生，计算机无法直接执行。
- **机械语言端**：机器码与形式化语言精确无歧义，但难以被人阅读、理解与检验。

两者之间存在一道难以逾越的鸿沟：从"人脑中的意图"到"机器可执行的代码"，需要程序员承担大量的翻译与转换工作。现有语言大多只覆盖鸿沟的某一侧——要么贴近机器（C、Rust），要么贴近人类可读代码（Python），却很少有语言试图**把整条链路作为一等公民**显式建模。

### 1.2 Matha 的主张

Matha 认为：**这条链路本身应当被语言显式表达，而非被编译器隐藏**。因此 Matha 将编程过程显式划分为三层：

1. **自然语言输入层** — 人用中英文表达意图
2. **数学核心层（机械语言）** — 以集合论与类型论为基础的数学公式化代码
3. **可读输出层** — 生成可被人阅读、对比、检验的命令

并且，Matha 拥有一套**自创符号体系**，作为贯穿三层的统一语法骨架——同一套符号既用于书写数学核心，也用于触发自然语言读取与命令输出。

### 1.3 为什么基于集合论与类型论

- **集合论**是现代数学的基础语言，足以表达数据、关系、映射、笛卡尔积等绝大多数程序结构。
- **类型论**为集合上的构造提供类型约束，保证构造的合法性与可检查性。
- 二者结合，使 Matha 的程序同时具备**数学可证性**与**工程可执行性**。

## 2. 语言愿景

Matha 致力于成为一门**自然语言驱动、数学形式化、可读可验证**的编程语言：

> 从自然语言中提取逻辑，构造为数学公式化的机械语言代码，再输出可读命令供人检验。

核心愿景可概括为一句话：

```
【*/意图/*】  →  #：机械语言  →  [] 可读命令
自然语言         数学核心          人可检验的输出
```

---

## 3. 设计哲学

| 哲学 | 含义 |
|------|------|
| **数学即代码** | 代码就是数学公式；程序构造即数学构造 |
| **符号即语义** | 每个符号有明确语义，符号体系本身就是语言的语法 |
| **标注防错** | `*/文字/*` 标注明确目标，在歧义产生之前消解歧义 |
| **可读即正确** | 若生成的命令无法被人读懂，则无法被信任 |
| **三层显式** | 自然语言 → 数学核心 → 可读输出，链路显式可见，不隐藏 |

---

## 4. 适用领域

| 领域 | 说明 |
|------|------|
| 形式化推理与规格 | 集合论 + 类型论天然适合表达数学规格与不变量 |
| 数据与集合处理 | 集合运算是核心能力 |
| 并发系统 | CSP（协程 + channel）适合并发与流水线 |
| 教学与研究 | 三层显式架构适合教授"从意图到执行"的全过程 |
| 自然语言驱动的快速原型 | 用自然语言描述意图即可生成可检验命令 |

## 5. 语言概貌：三段式 Hello World

下面用 Matha 符号体系展示一个完整的 Hello World，覆盖三层。

### 示例 1：输出问候

**① 自然语言输入层**

用 `【*/标注/*】` 包裹一段自然语言意图，标注为 `问候`：

```
【*/问候/*】
输出 "你好，Matha"
```

**② 数学核心层（机械语言）**

编译器从自然语言提取逻辑，生成机械语言代码。`#：` 表示生成/运行，`【*/问候/*】` 引用上述自然语言意图，`[]` 表示输出，`"你好，Matha"` 是字符串字面量：

```
#：【*/问候/*】
   [] "你好，Matha"
```

**③ 可读输出层**

执行后产出可被人阅读的命令结果：

```
[你好，Matha]
```

> **说明**：本示例为初步草案。`#：` 与 `[]` 的精确语义、字符串字面量的词法定义将在 [02-词法结构](02-词法结构.md) 与 [04-数学核心（机械语言）](04-数学核心（机械语言）.md) 中精化。

### 示例 2：集合求和（展示更多符号）

**① 自然语言输入**

```
【*/求和/*】
计算从 1 到 10 所有整数的和
```

**② 数学核心**

```
#：【*/求和/*】
   S = { x | 1 <= x <= 10 }
   ？sum = 0
   ？x >> S
      sum = sum + x
   [] sum
```

符号说明：

| 符号 | 此处的用法 |
|------|-----------|
| `S = { x | ... }` | 集合构造（集合论） |
| `<=` | 小于等于（关系运算） |
| `？sum` `？x` | 变量占位，`？` 可用任意字母替代（此处 `？sum` 等价于具名变量 `sum`） |
| `>>` | 步进迭代：`？x >> S` 表示 `x` 依次取 `S` 中的下一个元素 |
| `+` | 加法 |
| `=` | 赋值 |
| `[]` | 输出结果 |

**③ 可读输出**

```
[55]
```

> **说明**：`>>` 的迭代语义、`？` 与具名字母的替代规则已在 M1 走查确认（见 [02-词法结构](02-词法结构.md)）；`<=` 采用主流形式（见 [06-表达式与运算符](06-表达式与运算符.md)）。

## 6. 编译流程总览

Matha 程序从源文本到执行结果，经过以下阶段（详见 [15-编译执行模型](15-编译执行模型.md)）：

```
自然语言源文本
      │
      ▼  ① 词法分析（识别 Matha 符号体系）
      │
   Token 流
      │
      ▼  ② 自然语言前端解析（【*/文字/*】 段落 + 机械语言段落）
      │
   分层 AST（自然语言意图 + 机械语言骨架）
      │
      ▼  ③ 意图提取与映射（自然语言 → 数学核心构造）
      │
   数学核心 AST（集合论/类型论构造）
      │
      ▼  ④ 类型检查（*/文字/* 标注约束）
      │
   通过类型检查的 AST
      │
      ▼  ⑤ 生成命令（#： 触发，生成《文字》命令）
      │
   命令序列
      │
      ├──── ⑥a 可读输出（[] 输出，供人检验）
      │
      └──── ⑥b 执行（Python 运行时 / 目标代码）
```

## 7. 术语表

| 术语 | 英文 | 含义 |
|------|------|------|
| 机械语言 | Mechanical Language | Matha 的数学形式化核心层代码 |
| 自然语言前端 | Natural Language Frontend | 接收中英文自然语言意图的输入层 |
| 可读输出层 | Readable Output Layer | 生成可被人阅读命令的输出层 |
| 标注 | Annotation | `*/文字/*`，为字母/表达式附加语义标记 |
| 读取 | Read | `【】`/`〔〕`，从某来源提取内容 |
| 命令 | Command | `《文字》`，一个可执行/可生成的命令单元 |
| 分格 | Separator | `|`，分隔语法单元 |
| 占位 | Placeholder | `？`，可用任意字母替代的变量占位符 |
| 角 | Angle | `<<`，语义待细化（候选：角标/索引） |
| 下一个 | Next | `>>`，步进/迭代到下一个 |
| 生成/运行 | Generate/Run | `#：`，触发命令生成或执行 |
| 三段式 | Three-Stage | 自然语言 → 数学核心 → 可读输出 的链路 |
