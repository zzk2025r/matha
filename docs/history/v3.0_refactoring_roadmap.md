# Matha v3.0 重构路线图

> 从"全能上位语言"转型为"数学计算 DSL"，聚焦核心优势，放弃泛用性竞争。

---

## 1. 定位问题诊断

### 1.1 当前定位模糊

```
Matha 声称：
  ✅ 自然语言输入（类似 Wolfram Alpha）
  ✅ 数学形式化（类似 Lean/Coq）
  ✅ 可执行代码（类似 Python/Julia）
  ✅ 自成长引擎（类似自托管编译器）
  ✅ CSP 并发（类似 Go）
  ✅ 多语言前端（类似 Babel）

实际：
  ❌ 自然语言：正则匹配，不如 GPT-4
  ❌ 数学形式化：无类型检查，不如 Lean
  ❌ 可执行：Python 子进程，不如 Julia
  ❌ 自成长：模板拼接，不如 LLM
  ❌ 并发：模拟协程，不如 Go
  ❌ 多语言：仅 Python，不如 Babel
```

**结论**：每项能力都不如专业工具，"全能"导致"全弱"。

### 1.2 核心优势识别

| 优势 | 强度 | 说明 |
|---|---|---|
| **代码即数学** | ⭐⭐⭐⭐⭐ | 唯一将数学公式作为一等公民的语言 |
| **自然语言 + 形式化混合** | ⭐⭐⭐⭐ | 现有语言无此能力 |
| **可读可验证输出** | ⭐⭐⭐⭐ | 生成的命令可被人检验 |
| **结构化异常处理** | ⭐⭐⭐ | v2.3/v2.4 已实现 |
| **并发安全优化** | ⭐⭐⭐ | v2.4/v2.5 已实现 |

**核心定位**：**面向数学计算的自然语言可编程 DSL**

## 3. 重构路线图

### Phase 1: 核心聚焦（v3.0，8 周）

#### 1.1 移除泛用性组件

| 移除组件 | 原因 | 替代方案 |
|---|---|---|
| `src/codegen/web.py` | 通用 Web 代码生成 | 移除，专注数学 |
| `src/codegen/desktop.py` | 桌面应用代码生成 | 移除 |
| `src/codegen/game.py` | 游戏代码生成 | 移除 |
| `src/codegen/kernel.py` | 内核代码生成 | 移除 |
| `src/interop.py` | 多语言互操作 | 移除 |
| `src/multi_lang_frontend.py` | 多语言前端 | 简化为单一数学 DSL |
| `src/autonomous.py` | 自成长引擎（过度设计） | 简化 |

#### 1.2 强化核心能力

| 新增/强化 | 说明 |
|---|---|
| **LLM 意图解析** | Claude/DeepSeek 集成，替代正则匹配 |
| **MIR 代码生成** | 强化机械语言生成质量 |
| **类型检查** | 基于集合论的严格类型系统 |
| **可执行验证** | 生成的代码必须可执行且可验证 |

#### 1.3 API 简化

```python
# v3.0 简化 API
from matha import compute, prove, verify

# 自然语言计算
result = compute("计算 100 以内所有素数")
# 返回: [2, 3, 5, ..., 97]

# 数学证明辅助
proof = prove("√2 是无理数")
# 返回: 证明过程（可阅读的形式化证明）

# 代码验证
verified = verify("f(x) = x^2 是凸函数")
# 返回: True/False + 验证过程
```

### Phase 2: 性能优化（v3.1，4 周）

#### 2.1 LLVM 编译后端

- 集成现有 `llvm_backend.py`
- 支持 `--backend=llvm` 编译选项
- 预期 10-100x 性能提升

#### 2.2 JIT 缓存

- 编译结果缓存到 `.matha_cache/`
- 相同输入复用编译结果

#### 2.3 向量化

- 利用 LLVM SIMD 优化数值计算
- 自动向量化循环

### Phase 3: 生态建设（v3.2，4 周）

#### 3.1 IDE 支持

- VS Code 插件（语法高亮 + 补全）
- Jupyter Notebook 集成
- Vim/Neovim 插件

#### 3.2 包管理

- `matha-pkg` 包管理器
- 数学函数库（类似 NumPy）
- 形式化验证库（类似 Coq 库）

#### 3.3 文档与教程

- 数学计算教程
- 形式化证明指南
- API 参考文档

## 5. 兼容性与迁移

### 5.1 API 兼容性

```python
# v2.x 代码 → v3.0 迁移

# 旧 API
from src.enhanced_intent import EnhancedIntentParser
parser = EnhancedIntentParser()
result = parser.parse("计算 3 加 5")

# 新 API（兼容）
from matha import compute
result = compute("计算 3 加 5")

# 或保留旧 API
from src.enhanced_intent import EnhancedIntentParser
parser = EnhancedIntentParser(llm_parser=LLMIntentParser(...))
```

### 5.2 迁移工具

```python
# scripts/migrate_v2_to_v3.py
"""将 v2.x 项目迁移到 v3.0。"""

import re
from pathlib import Path

def migrate_file(filepath: Path):
    content = filepath.read_text()

    # 替换 import
    content = re.sub(
        r'from src\.(intent_parser|enhanced_intent) import',
        'from matha.intent import',
        content
    )

    # 替换 API
    content = re.sub(
        r'EnhancedIntentParser\(\)',
        'compute',
        content
    )

    filepath.write_text(content)
```

## 8. 结论

**Matha 不应成为"另一个 Python"**，而应成为**"数学计算的可验证 DSL"**。

核心转型：
1. **放弃**：通用编程、Web 开发、系统编程
2. **聚焦**：数学计算、形式化验证、科学计算
3. **差异化**：自然语言 + 数学公式 + 可验证输出

```
┌──────────────────────────────────────────────────────┐
│  Matha v3.0 口号                                      │
```
