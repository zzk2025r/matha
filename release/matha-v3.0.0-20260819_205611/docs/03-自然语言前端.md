# 03 - 自然语言前端

> 本章定义 Matha 的**自然语言前端**：用户用中英文自然语言表达意图的输入格式、解析规则、意图提取，以及自然语言到数学核心的映射。`*/文字/*` 标注在此层起**意图标识与歧义消解**的关键作用。

---

## 1. 定位

自然语言前端是三层架构的入口：

```
用户自然语言  ──→  自然语言前端  ──→  数学核心（mech_body）
【*/标注/*】          解析+映射          #：...
```

- **职责**：接收中英文自然语言意图，提取逻辑，映射为数学核心构造。
- **边界**：Matha 不追求解析任意自然语言，而是支持**受约束的自然语言子集**（§5）。超出子集的意图需用机械语言显式书写。

---

## 2. 自然语言输入格式

### 2.1 意图块语法

自然语言以**意图块**形式书写，由读取符号包裹标注：

```ebnf
<nl_block>     = <read_natural> ;
<read_natural> = ( "【" | "〔" ) , <annotation> , ( "】" | "〕" ) , <natural_lang> ;
<natural_lang> = { <nl_char> } ;
```

**形式**：

```
【*/标注/*】
   自然语言正文
```

- `【*/标注/*】`（或 `〔*/标注/*〕`）：标注此意图块的用途（如 `*/求和/*`、`*/问候/*`）。
- 标注后的自然语言正文为意图描述。

### 2.2 示例

```
【*/问候/*】
输出"你好，Matha"

【*/求和/*】
计算从 1 到 10 所有整数的和

【*/过滤/*】
从集合 S 中选出大于 5 的元素

【*/行程问题/*】
《小米在 c>>d 段 1/4 下车，求小米到 a 点距离》
```

> 用户手写自然语言可直接用 `《文字》` 命令字面量描述问题，由机械单元显式配合 `@:xxx，yyy` 设定与 `{ }` 整体块（见 [18 §9](18-示例程序集.md)）。

## 3. 中英文解析规则

### 3.1 双语支持

- 自然语言正文可为**中文**、**英文**或二者混排。
- 标注（`*/文字/*`）建议用简短标识符，中英均可：`*/求和/*`、`*/sum/*`。

### 3.2 解析流程

```
自然语言正文
    │
    ▼  ① 分词与词性标注（中文用 jieba 等；英文用空格分词）
    │
   词序列
    │
    ▼  ② 意图模式匹配（基于意图模板）
    │
   意图骨架
    │
    ▼  ③ 槽位填充（提取数值、变量、集合等参数）
    │
   结构化意图
    │
    ▼  ④ 映射为数学核心构造（§4）
    │
   mech_body
```

### 3.3 意图模板（草案）

每种意图标注对应一类模板。模板定义了该意图的自然语言模式、**必填槽位**与映射规则。必填槽位是映射成立所必需的参数；缺失时触发槽位追问（§5.4），而非直接拒绝。

| 标注 | 模式 | 必填槽位 | 映射目标 |
|------|------|---------|---------|
| `*/问候/*` | `输出"..."` | 文本 | `[] "..."` |
| `*/求和/*` | `计算从 A 到 B ... 的和` | 范围 A..B、累加对象 | 集合构造 + 迭代累加 |
| `*/过滤/*` | `从 S 中选出 条件 的元素` | 源集合 S、条件 | 集合构造 `{ x | x >> S | 条件 }` |
| `*/计数/*` | `统计 S 中满足 条件 的数量` | 源集合 S、条件 | 迭代计数 |
| `*/生成硬件/*` | `生成[设备类型][参数]` | 设备类型、规格参数（尺寸/分辨率等） | struct 构造 + 生成命令（见 §4.4） |

> **模板的粒度**：模板只负责把自然语言意图"骨架化"为结构化意图（意图类别 + 槽位），**不负责**把意图一步映射为完整 mech_body。从结构化意图到 mech_body 的逐级简化遵循数学核心的"段内 5 步固定顺序"（[04 §5.12](04-数学核心（机械语言）.md)）：命令 → 变量命令 → `？`公式 → 字母公式 → 输出。意图模板产出的结构化意图，正是这条简化链的**起点**（命令级）。
>
> 模板库随标准库扩展（见 [14-标准库概要](14-标准库概要.md)）。

## 4. 自然语言 → 数学核心的映射

### 4.1 映射原则

- **保语义**：映射前后语义一致，标注用于验证一致性。
- **可追溯**：每个映射步骤可追溯，便于可读输出层对比。
- **歧义消解优先**：映射前先消解歧义（§5）。

### 4.2 映射示例

**输入**：

```
【*/求和/*】
计算从 1 到 10 所有整数的和
```

**提取的结构化意图**：

```
意图: 求和
范围: 1..10
操作: 累加
```

**映射为数学核心**：

```
#：【*/求和/*】
   S = { x | 1 <= x <= 10 }
   ？sum = 0
   ？x >> S
      sum = sum + x
   [] sum
```

### 4.3 映射的触发

- `#：【*/标注/*】` 触发对意图块的执行：前端解析意图块，映射为 mech_body，交数学核心执行。
- 映射失败分两种情况，分别处理：
  - **必填槽位缺失**（模板已匹配，但参数不全）→ 触发**槽位追问**（§5.4），编译器主动询问缺失参数，用户补全后继续映射。
  - **意图超出子集**（无任何模板匹配）→ 编译器报错，提示用机械语言显式书写。
- 槽位追问是"模板+追问"策略（B 策略）的核心：它把"简洁输入"从**直接拒绝**转为**引导补全**，在不引入 AI 不确定性的前提下，扩展了可处理的简洁输入范围。

### 4.4 示例：简洁意图的逐级分解（"生成显示器"）

本示例演示一个**参数隐式、意图开放**的简洁输入如何被有效分解为命令逻辑。关键在于：自然语言前端不试图一步到位生成完整 mech_body，而是把意图交给数学核心的**段内 5 步固定顺序**（[04 §5.12](04-数学核心（机械语言）.md)）逐级简化。

**输入**（简洁、参数隐式）：

```
【*/生成硬件/*】生成显示器
```

**第 0 步：意图识别 + 槽位追问**

| 阶段 | 结果 |
|------|------|
| 意图类别 | 生成硬件（模板 `生成[设备类型][参数]` 已匹配） |
| 已识别槽位 | 设备类型 = 显示器 |
| 缺失槽位 | 规格参数（尺寸、分辨率） |
| 处理 | 触发槽位追问（§5.4）：编译器询问"请补充显示器规格：尺寸、分辨率" |
| 用户补全 | "27寸，4K" |

**结构化意图**（槽位追问后的产物，即简化链的起点）：

```
意图: 生成硬件
设备类型: 显示器
规格:
  尺寸: 27（单位: 寸）
  分辨率: 4K
```

**第 1–5 步：逐级简化为 mech_body**（按 04 §5.12 固定顺序，每级都是上一级的进一步简化）：

```
#：【*/生成硬件/*】生成显示器
#1：{
   #1：【生成显示器】                              ← ① 命令：从意图拆下的多重逻辑简化（这里拆为一条目标命令）
   @1：类型="显示器"，尺寸=27，单位="寸"，分辨率="4K"   ← ② 变量命令：带入变量、用数字/字母平替（NL→ML 过渡层）
   #1：？分辨率 = ？宽 * ？高                        ← ③ ？公式：真正自然语言，用？平替字母（通用结构，不绑定具体变量）
   #1：分辨率 = 3840 * 2160                         ← ④ 字母公式：？代入变量对号入座并计算（？→具体值）
   #1：[显示器：27寸/4K]…1（0/1）                    ← ⑤ 输出/结果 + 段级循环
   #：【文件】
}
```

**逐级简化的语义**（对应用户对 5 步顺序的权威定义）：

| 步骤 | 在本例中的角色 | 语义 |
|------|--------------|------|
| 自然语言意图 | `生成显示器` | 要说的话/要做的事（最上层） |
| ① 命令 | `#1：【生成显示器】` | 从上一级意图拆下的多重逻辑简化 |
| ② 变量命令 | `@1：类型=…，尺寸=27…` | 进一步拆解简化并赋值，带入变量，用数字/字母平替——**自然语言到机械语言的过渡层** |
| ③ `？`公式 | `#1：？分辨率 = ？宽 * ？高` | **真正自然语言**：把数学公式的字母用 `？` 平替与简单化；以 ② 的变量带入进行产生 |
| ④ 字母公式 | `#1：分辨率 = 3840 * 2160` | `？`公式带入变量对号入座的产物并进行计算 |
| ⑤ 输出/结果 | `#1：[显示器：27寸/4K]` | 计算结果产出 |

> **本例解决的问题**："生成显示器"这类简洁输入之所以能被有效分解，不是因为前端"理解"了显示器的语义，而是因为：
> 1. **模板匹配**把意图骨架化为"生成硬件 + 设备类型槽位"；
> 2. **槽位追问**补全了缺失的规格参数，避免直接拒绝；
> 3. **5 步逐级简化**把补全后的结构化意图，从"命令"逐级简化到"变量命令→？公式→字母公式→输出"，每一级都是上一级的进一步简化，最终落到可执行的 mech_body。
>
> 简洁性被"逐级简化"吸收，而非要求用户一次写全。

## 5. 歧义消解：标注的作用

自然语言的歧义是 Matha 前端的主要挑战。`*/文字/*` 标注从三个层面消解歧义：

### 5.1 意图级消解

标注确定意图类别，缩小解析空间：

```
【*/过滤/*】 选大于 5 的        → 过滤意图
【*/计数/*】 统计大于 5 的数量   → 计数意图
```

同样的"大于 5"，因标注不同而映射为不同构造。

### 5.2 槽位级消解

当自然语言中参数不明确时，标注提供约束：

```
【*/求和/*】 计算总和            → 缺少范围，需标注或上下文补充
```

### 5.3 类型级消解

标注可与类型标注结合（见 [05-类型系统 §7](05-类型系统.md)），消解数值类型歧义：

```
【*/求和/*】 计算 1 到 10 的和 */Int/*
```

### 5.4 槽位追问（B 策略：参数缺失时的引导补全）

当模板已匹配但**必填槽位缺失**时（如"生成显示器"缺尺寸/分辨率），不直接拒绝，而是由编译器**主动追问**缺失参数。这是处理简洁输入的核心机制。

**触发条件**：

```
模板匹配成功  ∧  必填槽位未填满  →  触发槽位追问
```

**追问流程**：

```
意图匹配
   │
   ▼  检查必填槽位
   │
   ├─ 全部填满 → 进入 5 步逐级简化（§4.4）
   │
   └─ 有缺失 → 编译器输出追问信息
                    │
                    ▼  用户以自然语言补全
                    │
                   回到"槽位填充"（§3.2 ③）
                    │
                    ▼  再次检查
                    │
                   循环直至填满 / 达追问上限
```

**追问信息格式**（草案，详见 [12-错误处理](12-错误处理.md)）：

```
[槽位追问] 意图"生成硬件"缺少必填参数：
  - 尺寸    : Int（带单位，如 27寸）
  - 分辨率  : String（如 4K / 3840*2160）
请补充以上参数，或用机械语言显式书写。
```

**追问上限**：为避免无限循环，设定最大追问轮次（默认 3 轮，可配置）。超过上限仍未补全 → 转为报错，提示用机械语言显式书写。

**与 §5.2 的区别**：

| 机制 | 触发 | 信息来源 |
|------|------|---------|
| §5.2 槽位级消解 | 标注提供约束，**静态**缩小解析空间 | 标注本身 |
| §5.4 槽位追问 | 槽位缺失，**动态**向用户索要参数 | 编译器与用户交互 |

> **设计取舍**：槽位追问保持规则解析的**确定性**——追问的槽位名与类型由模板静态定义，用户的补全仍走规则解析的槽位填充，不引入 AI 推断。代价是模板覆盖面仍有限；超出模板的意图仍走 §4.3 的"意图超出子集 → 报错"路径。

## 6. 受约束的自然语言子集

Matha 不解析任意自然语言，而是支持一个**受约束子集**：

| 约束 | 说明 |
|------|------|
| 意图必须标注 | 每段自然语言必须以 `【*/标注/*】` 开头 |
| 模板匹配 | 正文须匹配某意图模板的模式（§3.3） |
| 参数可识别或可追问 | 数值、变量、集合等参数须可识别；缺失时由槽位追问引导补全（§5.4），不要求一次写全 |
| 中英词汇表 | 使用受控词汇表（见下表） |

超出子集的自然语言（无模板匹配且无法追问），前端拒绝解析并提示用机械语言书写。

### 6.1 受控词汇表（草案）

| 类别 | 中文 | 英文 | 用途 |
|------|------|------|------|
| 通用动作 | 计算 / 输出 / 选出 / 统计 | compute / output / select / count | 通用意图模板动词 |
| 生成动作 | 生成 / 创建 / 构建 | generate / create / build | 生成类意图模板动词 |
| 硬件设备 | 显示器 / 键盘 / 鼠标 / 端口 | monitor / keyboard / mouse / port | 设备类型槽位取值 |
| 规格参数 | 尺寸 / 分辨率 / 频率 / 容量 | size / resolution / frequency / capacity | 硬件规格槽位名 |
| 资源类型 | 文件 / 文件夹 / 网站 / URL | file / folder / website / url | 资源字面量识别（[07-语句与控制流 §2.4.5](07-语句与控制流.md)） |

> 词汇表随模板库扩展（§3.3）。新增模板时同步登记其动词与槽位词汇。硬件资源在类型系统中以 struct 定义（见 [05-类型系统](05-类型系统.md) / [09-用户自定义类型](09-用户自定义类型.md)），例如：
>
> ```
> struct 显示器 = {
>    类型   : String
>  , 尺寸   : Int */约束*尺寸 > 0/*
>  , 单位   : String
>  , 分辨率 : String
> }
> ```

## 7. 解析深度：规则 vs NLP/AI（待确认）

自然语言前端的解析深度有两种候选方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **规则解析**（默认草案） | 确定性、可控、易验证、无外部依赖 | 覆盖面窄，模板需手工扩展 |
| **NLP/AI 模型**（候选） | 灵活、覆盖面广、容忍自由表达 | 不确定性、需 Python 生态（transformers/spacy）、难验证 |

**当前默认**：采用规则解析（契合 Matha"可读可验证"哲学）。
**后续可选**：在规则解析失败时，回退到 AI 模型辅助映射，但映射结果须经标注验证。

> 此项待用户确认（见计划文件待决策项 §5）。

## 8. 与可读输出层的衔接

自然语言前端映射后，原始自然语言与生成的数学核心均保留，供可读输出层进行**对比展示**：

```
【*/求和/*】 计算 1 到 10 的和        ← 原始自然语言
#：{ x | 1 <= x <= 10 } ... [] sum    ← 生成的数学核心
[55]                                  ← 可读输出
```

三层并排展示，人可逐层检验（详见 [13-可读输出层](13-可读输出层.md)）。
