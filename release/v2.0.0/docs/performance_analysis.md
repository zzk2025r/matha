# Matha 自成长引擎 — 性能分析报告 v2.1

## 性能基准测试

### 测试环境
- Python 3.14, Windows
- 单次 grow() 调用, max_iterations=5
- 每次测试独立 engine 实例

### 各场景耗时与优化效果

| 场景 | 总耗时 | 优化逻辑 | 字符变化 | 最终结果 |
|---|---|---|---|---|
| 简单加法 | ~190ms | 折叠×1, DCE×1, 传播×1 | 20→9 | result = 7.0 |
| 嵌套函数链 | ~10ms | 内联×3 + 折叠 + 传播 | 146→10 | result = 30.0 |
| 常量链(8步) | ~24ms | 折叠×1, DCE×3, 传播×1 | 120→94 | result = 21.0 |
| 多函数嵌套 | ~17ms | 无（多次调用不内联） | 170→170 | 不变 |
| 死代码+函数 | ~7ms | DCE×1 | 75→61 | result = 9.0 |
| 混合优化 | ~16ms | DCE×3, 折叠×1, 传播×1 | 189→154 | result = 75.0 |
| **总计** | **~265ms** | | | |

### 热点分析 (cProfile)

```
首次调用:
  ├─ interp.py 模块导入: ~170ms (含 domain builtins 构建)
  └─ 优化逻辑本身: ~137ms

第二次调用（懒加载后）:
  ├─ interp.py 缓存复用: ~2ms (76x 加速)
  └─ 优化逻辑本身: 同上
```

### 瓶颈结论

1. **主要瓶颈（已优化）**: 解释器模块导入耗时 ~170ms
   - **解决方案**: 类级缓存 `_interpret_cache`
   - 首次导入后缓存 interpret 函数引用
   - 后续调用直接复用，节省 ~168ms (98.8%)

2. **次要瓶颈**: dataclasses 装饰器注册 (~47ms)
   - 随模块单例化已消除重复开销
   - 仅首次导入时发生

3. **优化逻辑本身**: ~137ms，效率良好
   - 函数内联（多轮迭代）: ~30ms
   - 常量折叠/传播/DCE: ~20ms
   - 循环展开: ~5ms
   - 变量存活分析: <1ms

## 内存分配策略分析

### 当前策略（v2.1）
- 所有变量统一使用 Float 类型（T_FLOAT）
- 临时变量按序命名（t0, t1, t2...）
- **新增**: 变量存活范围分析 + 栈式命名

### 变量存活分析优化

```
策略：
  1. 收集所有顶层赋值变量及其首次/末次出现位置
  2. 计算存活区间 [first_occurrence, last_occurrence]
  3. 使用贪心区间着色算法，识别不重叠区间
  4. 复用槽位，将语义化命名替换为栈式命名 (v0, v1, ...)
```

**效果**: 减少命名空间污染，便于后续常量传播和死代码消除

### 建议改进（低优先级）
1. **变量存活范围分析**：识别短期存活变量，复用内存槽位 ✅ 已实现
2. **常量表优化**：将只读常量提升到常量表，减少重复分配
3. **栈式命名**：在函数体内使用栈帧式命名（减少全局变量） ✅ 已实现
